Annotate trial text

Press Annotate on a trial's summary, description or eligibility criteria, and a model you run (LM Studio, qwen3.5-0.8b-mlx) marks the terms of labels you define in Settings, piece by piece as it reads. Nothing is committed yet.

Architecture

Two layers: models, and tasks on top

Tasks only ever call ChatModel.chat(messages, schema), so the model behind them can change (another LM Studio model, or later your fine-tuned one) without touching a task.

Flow

What happens when you press Annotate

1 · Read the text ~ms

From trials.db; the read ends before the model runs.

2 · Cut it into pieces ~900 chars

Between paragraphs, then lines, sentences, words.

3 · Ask the model, 4 at a time 0.2–2 s each

All labels at once; JSON held to a schema whose labels are an enum; rules, and an example built from your labels' own examples.

4 · Find each term in its piece

Whole words, any case or line break, every place it appears. A term that isn't there, a generic word or a clause is dropped.

5 · Stream it a line per piece

Marks fade in as each piece is answered; the button counts pieces.

Storage

What's stored, and where: settings only

No migration, nothing new in trials.db or app.db. Annotations are recomputed on request (a second or two) and remembered in memory, so they never go stale when the model, labels or text change.

tri-al.toml [ai]settingsserver, model, labels (as [[ai.annotation.labels]]). Edited from Settings, which writes only what changed. Applies at once: each API worker reads it again when the file changes. TRI_AL_AI__* variables override it and lock those fields.
API worker memoryresultsThe last 256 annotated texts, keyed by text, model, server, labels and prompt version. Gone on restart.
BrowserresultsTanStack Query cache per trial text, keyed by the settings and the data version: coming back to a trial shows its marks at once.
trials.db, app.dbnothingThe text is read, never written.

Settings

Choose the model and define the labels

Server

Checked as you type: “Connected · 6 models”, or why not (“can't reach … is it running?”).

Model dropdown

From LM Studio's own API: which are loaded, format and quantization; embedding models left out. “Automatic” takes the first loaded one.

Labels

Name, description, examples and one of 8 colours from the chart palette. The model reads all three, and the examples become its worked example. Save writes only what changed; the switch turns AI off.

Measured on 8 real trials, 30 pieces

How a 0.8B model is asked

Three ways, judged by reading every answer (there are no reference annotations yet).

All labels, no rules or example

Clauses and generic words came back as terms:

  • “to block the sensory branches of the nerves” as a Condition
  • “patients”, “feasibility”, “impact”
  • once, a whole paragraph as 60 one-word terms

One request per label

Found more, but couldn't say “none”: every label got the same terms.

  • donanemab as a Condition, a Biomarker and an Assessment
  • 4× the requests for the same time

not chosen

All labels + rules + an example from your labels

Short terms, no collapse into words:

  • early Alzheimer's disease, lecanemab, placebo, CDR-SB
  • a hand-written example leaked its own terms; one built from the labels' examples fits any labels
  • 136 of 144 terms were in the text; the rest are dropped

chosen

Where it stands

Fast enough for real time; the 0.8B model's labels need checking

Quality now

  • Wrong labels: a glucose monitor as a Condition, “National Institute of Aging – Alzheimer's Association” as an Intervention, “men” and “women” as conditions
  • Misses: CDR (a scale) in eligibility text
  • Everything marked is really in the text (grounding), and it's quick: about a second a description

Next steps, in order

  • A small reference set (50–100 texts you annotate) to measure precision and recall; it's also what a fine-tuned model trains and is judged on
  • Compare bigger models from the dropdown (qwen3.5-2b, 4b): no code change
  • Your fine-tuned model as a plugin backend (add_model_backend); every task can use it
